# admin-web 部署文档（一键 HTTPS 发布接入共享基础设施）

> 口径：admin-web 以**普通接入方**身份复用共享基础设施（`semgravio-infra`：共享 nginx 是唯一
> 对外入口，绑 80/443；webnet 为共联网络）。**基础设施（共享 nginx、PostgreSQL、Redis、
> 预览网络等）不由本仓部署、不由本仓脚本修改**——那些归 infra 单元管辖；本目录只包含
> admin-web 自己的部署单元：前端镜像（多阶段，服务器侧构建）、Compose 编排、共享 nginx
> 接入配置、一键发布与运维脚本。
>
> 入口：`https://admin.semgravio.com`（80 统一跳转 HTTPS）。浏览器只请求同源
> `/api/admin/**`，经共享 nginx → 前端容器 nginx → admin 后端 BFF，不直连任何能力域。
>
> ⚠ **本档描述的两类动作要分清**：
> - **静态验证**（`bash deploy/validate.sh`）：只读仓库文件，零副作用，随时可跑；
> - **真实发布**（`deploy/release.sh`）：会改服务器状态。**首次真实发布前须由用户明确确认**，
>   且前置输入（BACKEND_URL 真实值、证书）齐备后再执行。本票（#96）的实施交付止于
>   脚本、配置、文档与静态验证——未执行任何真实服务器操作，下文凡「验收通过」类表述
>   均指确认后的操作步骤，其真实结果须如实补记，不得预先声称通过。

## 1. 角色与目录

部署物全部收在 `deploy/` 单目录（对齐 aiplatform 布局）；仓库根只留 Vite 构建必需的
`.env` / `.env.prod`（前端特殊性：Vite 约定构建配置必须居仓库根）与 `.dockerignore`
（构建上下文＝仓库根——pnpm workspace 需要全仓源码，同为前端特殊性）。

| 位置 | 内容 | 管辖 |
|---|---|---|
| 开发机 `deploy/` | `release.sh`（一键发布）、`server.sh`（运维入口）、`build-bundle.sh`（打包）、`smoke-remote.sh`（冒烟断言，两处共用）、`web.Dockerfile`＋`web.compose.yml`（生产镜像与编排）、`web-dev.compose.yml`（本地容器自验）、`env.web.example`（服务器 env 模板）、`nginx/`（前端站点模板＋共享接入 conf）、`certs/`（本地证书暂存，不入 Git）、`部署文档.md`（本档） | 本仓 |
| 服务器 `~/semgravio-admin-web/` | 应用部署单元（解包目录）：源码树 + REVISION + `deploy/certs/` + `.env.production` | 本仓发布写入 |
| 服务器 `~/semgravio-infra/` | 共享基础设施单元（含 nginx 门禁 `install-nginx-conf.sh`） | infra 仓 |
| 共享 nginx 容器内 | `conf.d/admin-web.conf`＋`certs/admin-web/`（门禁安装，热更） | 门禁唯一写入 |

## 2. 前置条件

### 2.1 开发机

- bash（Windows 用 Git Bash）、`git`、`ssh`/`scp`；
- SSH 私钥在 `~/ssh/semgravio-eu-1.pem`（ Semgravio 欧 1 服务器专用，权限 600）；
- 本仓库 clone（发布在仓库根执行；**工作区须干净**，见 §4 脏工作区门禁）；
- **无需安装 Node/pnpm**——依赖安装与生产构建都在服务器侧多阶段镜像内完成，开发机零构建依赖。

### 2.2 服务器

- Docker 与 Compose 插件可用；
- infra 已起栈且健康：共享 nginx 容器 `semgravio-nginx` healthy、`webnet` 网络存在、
  门禁脚本 `~/semgravio-infra/install-nginx-conf.sh` 在场——缺任一先按 infra 仓口径起栈，
  本仓发布脚本不会代劳（也不触碰 PG/Redis/预览网络）；
- 远端应用目录 `~/semgravio-admin-web/` 已建（首次发布前置输入时顺手 `mkdir -p`）。

### 2.3 连接参数（默认值与覆盖）

默认沿用 aiplatform：`ubuntu@3.70.172.160`，密钥 `~/ssh/semgravio-eu-1.pem`。
`deploy/release.sh` 与 `deploy/server.sh` 同套默认、同法覆盖：

| 变量 | 默认 | 说明 |
|---|---|---|
| `SERVER_HOST` | `3.70.172.160` | 服务器地址 |
| `SERVER_USER` | `ubuntu` | 登录账号 |
| `SSH_KEY` | `$HOME/ssh/semgravio-eu-1.pem` | 私钥路径 |
| `REMOTE_DIR` | `semgravio-admin-web` | 远端应用目录（相对 `$HOME`，绝对路径以 `/` 开头也可） |
| `INFRA_DIR` | `semgravio-infra` | 远端 infra 目录（门禁脚本所在） |

覆盖示例：`SERVER_HOST=1.2.3.4 SSH_KEY=~/.ssh/other.pem deploy/release.sh`。

## 3. 服务器一次性输入（均不入 Git、不进部署包）

开发机仓库根执行以下命令，创建远端目录并上传环境模板与已有证书（这些命令属于真实发布准备，
本次未执行）：

```bash
ssh -i ~/ssh/semgravio-eu-1.pem ubuntu@3.70.172.160 \
  'mkdir -p ~/semgravio-admin-web/deploy/certs'
scp -i ~/ssh/semgravio-eu-1.pem deploy/env.web.example \
  ubuntu@3.70.172.160:semgravio-admin-web/.env.production
scp -i ~/ssh/semgravio-eu-1.pem \
  deploy/certs/admin.semgravio.com_bundle.pem deploy/certs/admin.semgravio.com.key \
  ubuntu@3.70.172.160:semgravio-admin-web/deploy/certs/
ssh -i ~/ssh/semgravio-eu-1.pem ubuntu@3.70.172.160 \
  'chmod 644 ~/semgravio-admin-web/deploy/certs/admin.semgravio.com_bundle.pem && chmod 600 ~/semgravio-admin-web/deploy/certs/admin.semgravio.com.key'
```

在服务器 `~/semgravio-admin-web/` 下：

1. **环境值**：编辑 `.env.production`（模板 `deploy/env.web.example`），填 `BACKEND_URL`：
   - 源站口径：`http(s)://主机[:端口]`（webnet 内容器名直连，如 `http://semgravio-admin:8081`）；
   - **只填后端源站、不含 `/api/admin`**——前缀由容器内 nginx 保留转发。URI 原样转发示例：
     浏览器请求 `https://admin.semgravio.com/api/admin/auth/login` → BFF 收到
     `http://semgravio-admin:8081/api/admin/auth/login`（路径一字不差，重复拼接才会 404）；
   - 空值/占位值/带 `/api/admin` 的值：发布前置检查即拒绝（容器启动也会响亮失败）。
2. **证书**（申请/续期按 infra 既有人工口径，本部署单元只消费）：
   - 证书源目录 = 本目录下 `deploy/certs/`，固定文件名 `admin.semgravio.com_bundle.pem`（证书链）与 `admin.semgravio.com.key`（私钥）；
   - 权限保护：`chmod 644 deploy/certs/admin.semgravio.com_bundle.pem && chmod 600 deploy/certs/admin.semgravio.com.key`（私钥仅属主可读）；
   - 发布时经门禁复制进 infra 的 `nginx/certs/admin-web/`。

缺失任一项：`deploy/release.sh` 在**上传与构建之前**即非零退出，服务器状态零改动。

> **秘密值纪律**：证书、私钥、服务器环境真实值（`.env.production`）**不得提交 Git**、
> 不进入部署包（`.gitignore` ＋ 打包断言双保险）；**部署包**（`dist/admin-web-deploy-*.tar.gz`）
> 同样不得提交 Git（`dist/` 已整体忽略）——它只作开发机→服务器的传输介质，用完即弃。

## 4. 一键发布

开发机仓库根：

```bash
deploy/release.sh    # 阶段 == 0..5/6 ==：本地密钥 → SSH 连通 → 远端前置 → 打包 → 上传 → 服务器（解包 → 构建启动 → 门禁安装 → 就绪等待 → 冒烟）
```

- 链路任一阶段失败即非零退出；阶段输出 `== n/6 ==`，便于定位失败时点。
- 前置检查（远端检查在**上传与构建之前**执行）：SSH 连通 → 共享 nginx 健康 → webnet 存在
  → BACKEND_URL 已填且源站口径 → 证书/私钥在场 → 门禁脚本在场。
- 打包：`deploy/build-bundle.sh` 按 **HEAD** 导出已提交源码（`git archive`，恒 LF），写入
  `REVISION` 记录线上源码版本。
- **脏工作区门禁**：工作区有未提交改动时默认**拒绝打包**（部署包内容按 HEAD，与工作区
  不一致会失去 revision 意义）；确认带脏打包的逃生开关：`ALLOW_DIRTY=1 deploy/build-bundle.sh`
  （输出醒目警告，包内容仍按 HEAD）。
- 常用开关：

| 开关 | 作用 |
|---|---|
| `SKIP_BUILD=1 deploy/release.sh` | 复用 `dist/` 里最新的包，只走上传→发布（应急重发/回滚同款包） |
| `ALLOW_DIRTY=1 deploy/build-bundle.sh` | 带脏打包逃生开关（见上） |

## 5. 首次验收（真实发布由用户确认后执行）

发布脚本自动执行三项冒烟断言（运维 `deploy/server.sh smoke` 与发布共用同一脚本
`deploy/smoke-remote.sh`，同一组外部断言，经共享 nginx 公网入口、真实 SNI 判定，
实际状态码如实输出）：

1. `http://admin.semgravio.com/` → **301** 且 Location 为 `https://admin.semgravio.com/...`；
2. `https://admin.semgravio.com/` → **200**；
3. 未登录 `GET https://admin.semgravio.com/api/admin/auth/current` → **401**（正向鉴权证据；
   任何其他值都判失败，不会把 502/错误页当成功）。

人工补验（结果如实记录，不预先声称通过）：

- **根路径**：浏览器打开 `https://admin.semgravio.com/` 正常渲染登录页；
- **深层 history 路由**：直接打开/刷新一个非根路由（如 `https://admin.semgravio.com/system/user`）
  仍进入 SPA 而非 404——history 回退由容器内 nginx `try_files ... /index.html` 提供。命令行核验：
  `curl -sk --resolve admin.semgravio.com:443:127.0.0.1 -o /dev/null -w '%{http_code}' https://admin.semgravio.com/system/user`（在服务器上执行，期望 200）；
- **浏览器登录验收**：真实账号登录、动态菜单与业务页面走通——独立人工步骤，结果补记于此。

## 6. 重复发布与幂等

- **重复执行安全**：compose 显式 `name/image/container_name`，重复发布不会误删其他服务
  容器；共享 conf 更新走门禁（撞车即拒、语法门禁、失败自动回滚），不直接写共享目录。
- **解包不覆盖现网输入**：部署包由 `git archive HEAD` 生成（天然不含 `.env.production`/
  `deploy/certs/`），解包后脚本复核三项现网输入仍在。
- 日常重复发布就是重跑 `deploy/release.sh`；只是重启应用、看状态日志见 §7。

## 7. 更换证书

`deploy/certs/admin.semgravio.com_bundle.pem` / `deploy/certs/admin.semgravio.com.key` 换成新文件（保持文件名与权限：`chmod 600 deploy/certs/admin.semgravio.com.key`）
后重跑 `deploy/release.sh` 即可——证书与 conf 走同一门禁，冒烟通过即生效。

## 8. 日常运维（`deploy/server.sh`，连接参数同 `deploy/release.sh`，见 §2.3）

```bash
deploy/server.sh status    # 容器概览（semgravio-admin-web ＋ semgravio-nginx）
deploy/server.sh logs web      # 跟应用容器日志（semgravio-admin-web，最近 200 行起）
deploy/server.sh restart   # 重启应用容器——只重建容器运行状态，不重新构建镜像（秒级）；
                      # nginx 配置/证书更新不走这里，统一走 deploy/release.sh 发布门禁
deploy/server.sh smoke     # 重跑三项 HTTPS 冒烟断言（与发布同一脚本）
deploy/server.sh sh        # 登服务器交互 shell
deploy/server.sh help      # 打印用法（无参数同）
```

未知子命令：打印上述用法并以非零退出码（64）结束。

## 9. 常见失败排查

| 现象 | 排查 |
|---|---|
| 阶段 0/6 报找不到密钥 | 核对 `SSH_KEY` 路径与权限（600） |
| 阶段 2/6 远端前置 ✗ | 按输出逐项补齐：nginx/webnet 未起 → infra 起栈；BACKEND_URL 空/占位/带 `/api/admin` → 改 `.env.production`；缺 `deploy/certs/*.pem` → 安放证书；缺门禁脚本 → 核对 `INFRA_DIR` |
| 阶段 3/6 拒绝打包（脏工作区） | 先提交；或确认后 `ALLOW_DIRTY=1` |
| 阶段 5/6 就绪等待超时 | `deploy/server.sh logs web` 看构建/启动日志；常见：BACKEND_URL 非法致入口脚本退出、webnet 未接入 |
| 冒烟 301 断言失败 | 共享 nginx 80 未生效：确认门禁安装成功、conf.d 挂载热更是否加载 |
| 冒烟首页非 200 | `deploy/server.sh status` 看容器是否 Up；`deploy/server.sh logs web` 看前端 nginx 错误 |
| 冒烟 API 非 401 | 链路异常（502=后端源站不可达，核对 `BACKEND_URL` 容器名/端口；404=URI 前缀拼错；200=鉴权未生效，找后端） |
| 浏览器证书错误 | `deploy/certs/admin.semgravio.com_bundle.pem` 非完整链或域名不符，更换后重跑 `deploy/release.sh` |
